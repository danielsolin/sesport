## Findings deferred with reasons

1. `EntityMergeRepository.cs:100` moves source participant links to the
   target before its duplicate cleanup at line 213. The schema's unique
   `(activity_id, entity_id)` index in migration 023 rejects a merge when
   both entities link to one activity. A preliminary delete would avoid the
   exception but could lose `is_active`, represented entity, or organization
   metadata. This needs an explicit merge rule and isolated database test.
2. `tools/SESport.BroadcastImporter/BroadcastParser.cs:127-135` appends
   rendered rows and then filters out all broadcasts without descriptions.
   Rendered rows are built with a null description at line 386. Existing
   `BroadcastParserTests.cs:138` expects a rendered-only row to survive.
   Whether descriptions are mandatory needs a product decision before the
   parser and tests are changed together.
3. Database tests use the live project database from `.env`. In
   `AiRepositoryTests.cs:915`, stale-run cleanup updates all eligible runs,
   not just the test run. Several tests insert before `try/finally`, including
   `BroadcastFieldModelTests.cs:21`, `BroadcastParticipationServiceTests.cs:166`,
   and `ActivityEditPageServiceTests.cs:23`. Some also create broadcasts near
   `UtcNow`. An isolated database or safer fixtures are needed before running
   these suites against the active target.
4. `DashboardRepository.cs:128` still computes `missing_description`, and
   `DashboardModels.cs:25` still exposes it after the dashboard UI stopped
   using it. Removing that projection changes a positional model and its
   Web test constructors; deferred as a coordinated cleanup.
5. `AiJobRunRepository.cs:974-999` accepts a configurable stale-run age but
   always records "Run timed out after 1 hour." The current test at
   `AiRepositoryTests.cs:957` expects that literal. Update both together
   when the unsafe database-backed test can run in isolation.
6. `AiJobPostProcessor.cs:127-207` still performs person updates, source
   replacement, and application marking across separate repository calls.
   The marker order is fixed, but a crash can leave partial facts or sources.
   A transaction and retry/catch-up design cross service boundaries.
7. `EntityMutationRepository.cs:751` now has a transaction; other multi-step
   activity and broadcast saves were not broadly reworked. For example,
   `ActivityEditPageService.SaveAsync` coordinates saving, participation
   marking, and hiding broadcasts. It needs a defined recovery policy before
   a cross-repository transaction is introduced.
8. `bin/db-mark-baseline-applied.sh:54-59` updates the baseline checksum on
   conflict, which could mask drift after another invocation. Changing it
   needs an isolated database and a verified recovery procedure.
9. `admin-broadcasts.js:969` hard-codes a 4,000 ms polling interval, and
   `AiRunToolTracePresenter.cs:1085` hard-codes a 120-character preview.
   Both are tunable behavior under the project rule; moving them into options
   requires following their host configuration and UI callers together.
10. The required inventory includes 107 pre-existing lines over 100 chars:
    76 in the applied baseline migration, 17 in source, 12 in the solution,
    and 2 in tests. No added or edited line exceeds the limit. Reformatting
    the applied baseline could invalidate its migration checksum.
11. `AGENTS.md` says `jobs/` is excluded from public Git, but `git ls-files`
    shows tracked active job instructions and earlier reports. This report
    was added in `0588c2ba`. Tracking policy for other jobs remains unclear.
