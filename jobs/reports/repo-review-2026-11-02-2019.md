## Findings

1. **High - Passwordless login links used the request Host. Fixed.**

   The original implementation built emailed URLs from Request.Scheme and
   Request.Host. With AllowedHosts set to *, a requester could put the raw
   one-time token in a link using an attacker-controlled Host.
   **Fixed and statically checked:** MemberAuthService now uses the validated
   MemberAuth:PublicBaseUrl setting. The controller no longer passes the
   request. The existing service test now checks configured production,
   development, and local origins; the test was not run. The setting requires
   an absolute HTTP(S) origin without credentials, path, query, or fragment
   (src/SESport.Web/Services/MemberAuthService.cs:88-131).
   .env.example:15 provides the production URL; src/SESport.Web/README.md:95-98
   documents per-site values.

2. **High - A Data integration test could fail unrelated runs. Fixed.**

   The original test called a global update that marks every running row older
   than the cutoff as failed. It uses the configured PostgreSQL connection and
   cleans up only its own inserted row
   (tests/SESport.Data.Tests/Data/AiRepositoryTests.cs:915-967;
   tests/TestSupport/PostgresTestDatabase.cs:12-16).
   **Fixed and statically checked:** the test now calls
   FailStaleRunningRunsForJobAsync with its unique generated job ID
   (tests/SESport.Data.Tests/Data/AiRepositoryTests.cs:915-944). That
   repository path adds a job_id filter
   (src/SESport.Data/AI/AiJobRunRepository.cs:986-1030); the production
   timeout worker keeps the existing global sweep. The test now expects
   exactly one updated row. It was not run.

3. **Medium - Page fetching can reach private addresses through DNS.**

   WebPageUrlPolicy blocks private IP literals and selected local names, but
   does not resolve hostnames (src/SESport.Core/WebPages/WebPageUrlPolicy.cs:
   70-94). Playwright navigation has no request routing
   (src/SESport.MCP/WebPages/WebPageBrowserPageFetcher.cs:212-225, 548-559);
   the effective URL is checked after navigation
   (src/SESport.MCP/WebPages/WebPageFetchOrchestrator.cs:965-987).
   A public-looking hostname resolving to a private address, or a browser
   subrequest to one, can reach internal services before that check.
   **Deferred:** define egress controls for DNS, browser subrequests, HTTP,
   curl, redirects, and OCR downloads.

4. **Medium - Push endpoints can direct server requests to internal hosts.**

   Watches accepts any bounded HTTPS endpoint and stores it
   (src/SESport.Web/Pages/Account/Watches.cshtml.cs:155-179, 238-304).
   The notification sender later passes the stored endpoint to the Web Push
   client (src/SESport.Web/Services/MemberPushNotificationSender.cs:59-87).
   An authenticated member can register an internal HTTPS destination and
   cause server-side requests when a watched activity notification is sent.
   **Deferred:** constrain provider endpoints and server egress together.

5. **Medium - AI schema validation skips active constraints.**

   The array branch checks type and minItems but returns without validating
   items or maxItems (src/SESport.AI/Protocols/ResponsesOutputValidator.cs:
   413-431). Integer validation also skips minimum
   (same file:386-395). The active person-data schema requires non-negative
   height and weight (src/SESport.AI/Schemas/find-person-data-output.json:
   11-23), but AiJobPostProcessor accepts any Int32 value and persists it
   (src/SESport.Web/Services/AiJobPostProcessor.cs:398-429).
   Malformed model output can therefore store negative measurements.
   enum, format, and minLength constraints are also not enforced.
   **Deferred:** add focused validator cases and verify all active schemas.

6. **Medium - Entity merge can violate unique and check constraints.**

   EntityMergeRepository moves activity links before deleting duplicates
   (src/SESport.Data/Entities/EntityMergeRepository.cs:96-107, 212-218).
   If both entities link to one activity, migration 023's unique
   (activity_id, entity_id) index rejects the update
   (database/migrations/023_database_sanity_fixes.sql:1-2).
   A direct source-target entity link is rewritten to a self-link before the
   later cleanup (src/SESport.Data/Entities/EntityMergeRepository.cs:634-670);
   the baseline distinct-entity check rejects it (database/migrations/001_baseline.sql:369-375).
   Existing merge tests use separate activities
   (tests/SESport.Data.Tests/Data/AdminRepositoryTests.cs:1275-1300).
   **Deferred:** define duplicate participant metadata retention, then verify
   using an isolated PostgreSQL test target.

7. **Medium - Changing an entity type can retain person measurements.**

   The edit view hides person fields but leaves their controls enabled
   (src/SESport.Web/Pages/Admin/Entities/Edit.cshtml:199-230).
   JavaScript only changes the hidden state
   (src/SESport.Web/wwwroot/Admin/js/admin-forms.js:150-201).
   ValidateEntity rejects gender and participation fields for non-person
   entities but does not clear or reject birthdate, height, or weight
   (src/SESport.Web/Pages/Admin/Entities/Edit.cshtml.cs:442-497).
   EntityMutationRepository writes those submitted values on update
   (src/SESport.Data/Entities/EntityMutationRepository.cs:359-407, 860-870).
   The baseline schema constrains gender by type but not these measurements
   (database/migrations/001_baseline.sql:345-350).
   Changing a populated Person to another type can leave person measurements
   attached to that non-person record.
   **Deferred:** establish server-side handling for person-only fields when
   an entity changes type and cover the transition with tests.

8. **Review required - Migration 014 may discard stored participant results.**

   Migration 013 renames the prior result-set table to
   activity_participant_ai_results
   (database/migrations/013_activity_participant_ai_results.sql:5-6).
   Migration 014 then drops and recreates that table without copying rows
   (database/migrations/014_activity_participant_ai_result_values.sql:1-3).
   Its test asserts the drop but not data preservation
   (tests/SESport.Data.Tests/Database/PostgresMigrationTests.cs:475-490).
   If rows existed when migration 014 ran, they were lost.
   **Deferred:** applied migration state and recoverable data require a
   database/backup review; rewriting an applied migration is unsafe.
